# 白云HSD开发者部落 Web 项目约定

本文件是本项目的设计与实现基线。后续参与项目的开发者和智能体在设计、修改或实现页面前，必须先阅读并遵守本文件。

## 1. 项目身份

- 产品名称统一使用：**白云HSD开发者部落**。
- 英文辅助名称可使用：`Baiyun HSD Developer Community`。
- 不再将“华为HSD联盟”作为产品主名称。
- 华为开发者生态、华为 ICT 学院只作为项目背景、技术生态或合作体系说明，不得替代产品名称。
- 未确认品牌授权前，不直接使用华为 Logo、Huawei ICT Academy 标识或官方视觉资产。
- 品牌口号：**鸿蒙启航，共赴星河万里**。

## 2. 当前设计基线

当前设计以桌面端首页为主基线：

- 桌面端设计稿：`../白云HSD开发者部落-首页设计稿.png`
- 移动端设计稿：`../白云HSD开发者部落-首页设计稿-移动端.png`
- 桌面端设计宽度：`1440px`
- 移动端设计宽度：`390px`

桌面端是当前主要评审对象。移动端采用同一套内容和品牌系统进行响应式重排，不是将桌面页面等比例缩小。

## 3. 设计风格

### 3.1 整体气质

设计关键词：

- 科技
- 权威
- 克制
- 校园活力
- 项目真实感
- 内容可信度

整体风格定位为：**正式科技门户 + 校园创新社区**。

页面需要同时满足：

1. 面向学校、老师和合作方时具有专业度与可信度。
2. 面向学生和招新对象时具有活力、参与感和成长氛围。
3. 能容纳技术研发、摄影媒体、活动策划和人才成长四种内容，不将网站做成单一技术社团官网。

### 3.2 视觉原则

- 使用大面积留白、清晰栅格和强标题建立秩序。
- 使用深红作为品牌强调色，近黑作为科技与项目区域的承载色。
- 正文区域保持浅色、克制、易阅读。
- 页面以整块横向内容区域组织信息，避免堆叠大量悬浮卡片。
- 卡片只用于确实独立、可点击或需要比较的信息。
- 使用真实项目、活动、作品和成员故事建立信任，不使用空泛品牌口号填充页面。
- 图片素材未提供时必须使用明确的“素材位”占位，不得擅自挪用需求资料中的海报。

### 3.3 禁止的视觉模式

- 禁止紫色、蓝紫色渐变作为默认科技风。
- 禁止三列同质化“图标圆圈 + 标题 + 两行介绍”的模板式布局。
- 禁止所有模块统一使用大圆角、强阴影或玻璃拟态。
- 禁止用装饰性气泡、波浪、漂浮圆形填补空白。
- 禁止使用 Emoji 作为正式页面装饰。
- 禁止所有内容居中排版。
- 禁止将用户提供的宣传海报直接作为网站 Banner、背景或内容图片。
- 禁止把桌面页面直接缩放后当作移动端页面。

## 4. 设计令牌

以下令牌是当前原型的推荐值。实现时应统一定义为 CSS 变量，不要在组件中散落硬编码颜色。

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| 品牌红 | `#B1202B` | 主按钮、快讯标签、重点数字、状态强调 |
| 深色背景 | `#211F1E` | 项目成果区、页脚、快讯主体 |
| 深色卡片 | `#302D2A` | 精选项目内容 |
| 暖白背景 | `#F4F0EB` | 四大中心、成员成长等品牌内容区 |
| 冷浅灰背景 | `#F5F6F7` | 新闻、活动、资源等信息区 |
| 图片占位灰 | `#DEDAD5` | 未提供正式素材时的占位 |
| 主要文字 | `#1F1D1C` | 标题和正文 |
| 次要文字 | `#77716B` | 辅助说明和元数据 |
| 分割线 | `#E2DFDB` | 卡片、列表和区块边界 |

### 4.1 圆角与阴影

- 普通按钮和内容块圆角以 `4px–8px` 为主。
- 只有浏览器外框、移动设备外框等演示容器可以使用更大圆角。
- 正式页面尽量少用阴影，优先通过背景、边框和间距建立层级。

### 4.2 排版

- 中文优先使用清晰的现代无衬线字体。
- 标题使用粗字重和紧凑行高，正文保持舒适行高。
- 桌面端正文不得小于 `16px`；设计缩略图中的小字号不代表生产实现字号。
- 正文每行建议控制在 45–75 个字符。
- 页面必须保持明确的 `H1 → H2 → H3` 语义层级。

## 5. 桌面端设计框架

### 5.1 页面栅格

- 设计视口：`1440px`。
- 主要内容宽度建议：`1240px–1280px`。
- 左右安全边距建议：视口宽度的 `5%–6%`。
- 信息区优先采用 `12` 列栅格。
- 各模块使用完整的横向背景区分，不依赖悬浮卡片拼接整页。

### 5.2 首页模块顺序

首页按以下顺序组织，未经确认不得随意打乱：

1. 顶部导航
2. 品牌 Banner
3. HSD 快讯
4. 核心数据
5. 新闻与公告
6. 四大中心
7. 真实项目
8. 近期活动
9. 媒体画廊
10. 成员成长
11. 资源中心
12. 招新行动区
13. 页脚

### 5.3 顶部导航

建议导航项：

- 首页
- 部落介绍
- 四大中心
- 项目成果
- 活动中心
- 媒体画廊
- 资源中心
- 结果中心
- 加入我们
- 登录

导航保持单层、简洁。登录是辅助入口，不应比主要内容更抢眼。

### 5.4 Banner

- 全站一级页面统一使用 `1440 × 420px` 的桌面端页头，其中顶部导航高 `64px`，主体内容高 `356px`。
- 所有一级页面共用同一导航骨架、品牌标识、激活态红色下划线和登录入口；页面切换时只改变 Banner 主体的信息结构。
- 首页使用深红与近黑的左右分屏，左侧承载品牌口号和主要行动，右侧预留官网主视觉素材位。
- 部落介绍使用暖白背景、HSD 轮廓字与关键数据，强调组织身份与可信度。
- 四大中心使用近黑四象限结构，表现四个中心平等协作的关系。
- 项目成果使用近黑网格舞台和精选项目展示位，当前重点项目为“智巡先锋”。
- 活动中心使用日期与近期活动构成视觉主体，优先回答“接下来有什么”。
- 媒体画廊使用编辑部式非对称图片网格，正式素材到位后替换占位区域。
- 资源中心使用可扫描的资源条目，所有条目先进入详情；当前未接入文件必须明确显示禁用状态，不得承诺登录后即可下载。
- 加入我们使用深红行动区与四方向入口，突出招新申请。
- 登录页不作为普通内容 Banner；使用独立任务页头，并明确只有个人资料、申请进度、结果中心和成长记录等内容需要登录。
- Banner 图片必须单独设计或使用经授权的正式照片。
- 不使用用户提供的宣传海报充当 Banner。
- 首屏主行动建议为“了解部落”，次行动为“查看招新”。
- 当前 Banner 设计总览与独立导出图位于 `../设计稿/页面Banner/`。

### 5.5 HSD 快讯

快讯位于 Banner 下方、核心数据和正式新闻之前。

快讯用于一句话可以说清的短时效信息，例如：

- 招新报名开放
- 报名即将截止
- 活动地点变更
- 临时通知
- 赛事结果提醒

快讯不是正式新闻。正式新闻应包含标题、正文、图片、作者、时间和详情页。

### 5.6 四大中心

四大中心平等呈现：

1. 白泽开发中心
2. 新媒体中心
3. 拓维策划中心
4. 人才发展中心

四大中心共同构成“研发 → 传播 → 策划 → 成长”的协作链路，不得将其他中心处理成技术部门的附属模块。

### 5.7 项目成果

当前首页项目展示顺序：

- 精选项目：**智巡先锋**
- 项目列表 01：智学领航
- 项目列表 02：小白云（校园服务）
- 项目列表 03：智能伴侣（HarmonyOS）

智巡先锋需要占据更大的精选项目位置，展示：

- 项目解决的问题
- 核心技术方案
- 项目演示素材
- 合作信息
- 赛事成果

小白云作为列表项目展示，不再占据首页精选项目主位。

### 5.8 媒体画廊

媒体画廊是首页的重要内容区，不是附属栏目。展示内容可包括：

- 活动摄影
- 海报作品
- 短视频封面
- 宣传片
- 人物专访
- 推文与品牌作品

采用一张主要作品搭配多张次要作品的非对称布局。

## 6. 内容与权限原则

### 6.1 默认公开

大部分内容无需登录即可查看：

- 部落介绍
- 四大中心
- 项目成果
- 新闻公告
- 活动详情
- 媒体作品
- 成员风采
- 公开资源
- 招新说明

### 6.2 按需登录

只有与个人身份、个人数据或个人操作相关的功能，在点击后要求登录：

- 编辑个人资料
- 查看成员个人信息
- 查看结果中心中的招新录取与阶段考核
- 查看个人成长记录
- 查看申请进度
- 提交或取消活动报名
- 确认内部资源身份（真实文件接入后才可提供下载）
- 查看内部比赛或成员资料

不要在用户尚未进行个人操作前强制登录。

### 6.3 公开人员与中心详情

- `/people/core`、`/people/members` 以及四个 `/centers/:slug` 详情页均为公开路由：`baize-development`、`new-media`、`tuowei-planning`、`talent-development`。
- 公开人员名录与中心详情可以展示已批准的脱敏成员信息和中心归属，不得将个人操作或个人记录带入匿名页面。
- 头像必须走统一解析规则：上传头像后自动用于公开成员展示，不提供独立公开开关；未上传或移除时展示白底 HSD 默认头像。

### 6.4 资源详情与文件动作

- 资源列表项必须优先进入 `/resources/:slug` 站内详情，列表点击不得直接触发下载。
- 详情页需要先说明格式、版本、权限、文件状态和使用范围，再提供阅读、外部访问或下载动作。
- 真实文件、接口或对象存储未接入时，文件按钮必须明确显示“文件暂未接入”并保持禁用；不得创建虚假文件、空链接或模拟下载成功。
- 内部资源详情可以公开浏览；未登录时可提供身份确认入口并保留来源路由，登录后隐藏该入口，但未接入文件仍保持禁用。

### 6.5 媒体专题与灯箱

- `/gallery/:slug` 使用全幅媒体承载：照片或品牌素材位铺满图片区，标题与说明放在透明到深色的暗层上，不得在媒体内部嵌套灰色素材框。
- 未获得正式授权图片时只使用品牌素材占位，不得使用需求海报、参考截图、随机人物照片或未授权素材。
- 灯箱必须支持鼠标和 `ArrowLeft`、`ArrowRight`、`Escape`；打开时聚焦关闭按钮并锁定背景滚动，关闭时移除滚动锁并把焦点还给触发照片。
- 图片加载失败时必须在原位切换为同尺寸 HSD 品牌降级面；标题、说明和灯箱导航继续可用，素材或图片地址变化后重置失败状态。

### 6.6 结果中心边界

- `/member/results` 属于个人数据，必须登录后访问，并通过 `redirect` 在演示登录后续接原路由；旧 `/assessment-results` 登录后只做兼容跳转。
- 用户端只展示当前有效的招新录取和阶段考核结果、三个志愿、白泽意向方向、最终归属与一名负责人。
- 不得展示完整历史、调剂过程、分数、排名、公开评语、管理员内部备注、报到时间、地点、材料、确认加入或放弃名额。
- 当前 TypeScript 数据只是前端语义 Mock，不代表真实数据库字段、后端发布状态或正式成员记录。

### 6.7 公开荣誉与成员详情

- 核心人员与全体成员名录最多展示三条重点荣誉；仅输出审核通过、成员选择公开的记录，无公开荣誉时不显示空标签或占位。
- 成员卡整卡进入公开 `/people/:id`；详情页可以展示脱敏资料和全部公开、审核通过的荣誉。
- 公开成员详情不得输出联系方式、考核结果、成长记录、申请进度、内部备注、证明材料地址、未公开荣誉或审核失败记录。
- 不按荣誉数量、级别或时间生成公开排行榜；荣誉数量不得破坏同一名录中的卡片等高。

### 6.8 Footer 非商业声明与密度

- 全站 Footer 必须固定显示：“本平台由学生社团自主建设，仅用于社团管理与校园交流，站内内容及图片不作任何商业用途。”
- 桌面底栏顺序固定为版权、非商业声明、帮助中心；平板允许声明独占一行；手机按相同顺序纵向排列。
- Footer 主体上下间距固定为 `54px 39px`，底栏最小高度为 `52px`。
- 帮助中心链接在手机端必须保持不小于 `44px` 的可操作高度。
- 不得通过缩小正文、移除入口或降低文字对比度来压缩 Footer。

## 7. 响应式规则

### 7.1 原则

- 桌面端、平板和手机使用同一个 Web 项目。
- 使用 CSS 响应式布局自动适配，不建设内容重复的独立移动站。
- 响应式的目标是重新编排内容，不是按比例缩小。

### 7.2 建议断点

| 断点 | 布局 |
| --- | --- |
| `>= 1280px` | 完整桌面布局 |
| `1024px–1279px` | 紧凑桌面或平板横屏 |
| `768px–1023px` | 平板双列布局 |
| `< 768px` | 手机单列布局 |

### 7.3 手机端变化

- 导航折叠为菜单按钮。
- Banner 由左右两栏改为上下结构。
- 核心数据改为 `2 × 2`。
- 新闻、活动、中心和资源改为单列。
- 媒体画廊改为一张主图加双列次图。
- 成员故事可使用横向滑动列表。
- 所有触控目标不得小于 `44px`。
- 保留快讯，但只显示一条短消息并允许横向切换。

## 8. 可访问性与交互

- 正文颜色对比度达到 WCAG 2.1 AA。
- 所有交互元素必须有键盘焦点状态。
- 不使用颜色作为唯一状态表达方式。
- 表单标签不得只依赖 placeholder。
- 按钮文案使用明确动作，例如“提交招新申请”，不要只写“提交”。
- 加载、空状态、错误和成功状态必须在原型与 PRD 中定义。
- 删除、权限变更等敏感操作必须二次确认。

## 9. 原型与实现关系

- 原型中需要完整呈现需求范围，即使部分功能在首个开发阶段暂不实现。
- 未实现功能应使用真实页面结构和状态说明，不使用空白页代替。
- 原型不是最终接口实现，但页面、模块、状态和权限边界必须可追溯到 PRD。
- 桌面端和移动端原型应共享相同内容结构与数据含义。

### 10.1 结果中心与预备成员考核约定

- 主站中已有 `/member/results` 用户端结果中心、`/assessment-results` 兼容跳转和 `/join/apply` 三步报名表；管理端已有 `/admin/recruitment` 前端原型。真实 API 与数据库仍按本节与完整规格继续实现。
- 个人端只显示本人当前有效结果，不显示完整考核时间轴、调剂过程、内部备注、分数、排名、公开评语、报到安排、确认加入或放弃名额。
- 26 级入库参与者初始身份为预备成员并享有全平台正常使用权；只有达到录取条件后才创建正式成员关系并进入对应中心数据源。
- 志愿最多三个且不得重复。白泽只能作为第一志愿；选择白泽时必须额外选择一个白泽方向，白泽方向不占志愿名额。第二、第三志愿和所有调剂目标都不得出现白泽。
- 新媒体、拓维策划、人才发展通过一轮面试即可转正；白泽必须按第一轮、第二轮、第三轮顺序推进，第三轮通过后才能转正。
- 调剂决策在线下完成。系统只允许授权管理员直接录入最终普通中心或未录取结果，不实现线上调剂工作流。
- 管理端使用四中心分组、名单表格、筛选、详情抽屉和二次确认，不使用阶段看板，不允许在表格行内直接改变身份结果。
- 用户端与管理端当前共用一个 Nuxt Web 工程，但必须使用独立布局与导航。`default.vue` 承载官网和成员页面，`admin.vue` 承载管理工作台；管理端不得复用官网顶栏或把管理入口暴露为普通公开导航项。
- 两端可以共享品牌设计令牌、登录会话、领域类型、校验规则和 API 契约，不应共享为具体业务页面定制的展示组件。后续只有在管理端需要独立发布节奏、独立基础设施或合规隔离时，才拆成两个部署。
- 前端路由保护只用于体验和导航控制；真实后端接入后，所有管理读取与写入 API 必须再次校验联盟总负责人或对应中心负责人的权限。
- 内部备注和审计记录仅后台可见。个人端对调剂后录取统一显示“已录取”和最终中心。
- 部落介绍、中心详情和公开成员名录只读取统一正式成员关系；预备成员只进入个人中心与招新数据。当前人员 ID 只允许由会话 Store 持有，其他 Store 必须按该 ID 查询档案。
- 头像上传后自动公开，移除或未上传时使用默认 HSD 头像；`avatarVisible` 只能作为派生展示状态，不得作为可编辑偏好。
- 后端技术栈未确认。本轮实现计划只允许创建可替换的前端领域类型、Pinia Mock 状态和数据访问边界，不得声称已经完成数据库写入或原子同步。
- 完整确认规格：`docs/superpowers/specs/2026-07-30-recruitment-results-system-design.md`。

### 10.2 桌面管理平台约定

- 管理端主验收尺寸为 `1440px` 和 `1366px` 桌面 Web。侧栏宽度为 `252px`，固定覆盖完整视口高度；长页面和整页截图不得在侧栏下方出现浅色或灰色空档。
- 七个一级业务域固定为：工作台、招新与考核、组织与成员、项目与活动、内容与门户、媒体与资源、系统与权限。管理路由、导航和页面标题必须使用同一领域命名。
- 官网导航和管理导航必须隔离。普通公开导航不得出现管理入口；管理页面只提供“返回官网”。
- 列表型页面默认使用“页面标题 + 核心指标 + 搜索/筛选 + 高密度表格或素材网格 + 详情抽屉”的结构。宽表格只在容器内部滚动，不得导致根页面横向溢出。
- 草稿保存、提交审核、确认发布和下架是不同状态。不得把“保存”当作“发布”，不得允许内容从草稿直接跳过审核。
- 身份、考核结果、对外发布、权限、资源版本和永久删除属于高风险操作，必须展示影响范围并二次确认；真实系统还必须写入不可由普通管理员修改的审计日志。
- 首页结构由用户端设计基线控制。管理端只能在固定槽位容量内选择和排序快讯、新闻、项目、活动、媒体专题和资源，不允许随意删除首页模块。
- 媒体文件采用对象存储思路：浏览器分片直传，服务端保存元数据和引用关系，异步生成缩略图/转码/病毒扫描，审核通过后才可公开选择。数据库不得直接保存大量原始图片和视频二进制。
- 学习资料必须保留版本历史、访问范围、发布状态和站内详情；下载应使用短时签名地址。PDF 预览、Office 转换、病毒扫描和访问日志在后端接入前必须诚实标记为未实现。
- 管理端前端路由守卫只承担体验控制。正式后端必须对每个读取与写入接口再次校验角色、动作权限、中心数据范围和资源归属；前端隐藏按钮不能替代服务端授权。
- 当前管理端所有数据和操作均为 TypeScript Mock 原型，不得在文案、测试或交付中声称已写入数据库、对象存储或真实审计系统。
- 完整确认规格：`docs/superpowers/specs/2026-07-30-admin-platform-design.md`。

## 11. 开发与验收要求

页面实现或修改完成后至少检查：

- `1440px` 桌面端布局。
- `1366px` 笔记本布局。
- `768px` 平板布局。
- `390px` 手机布局。
- 是否出现横向滚动。
- 导航、按钮和表单是否可使用键盘操作。
- 快讯、新闻、活动和项目是否使用正确的数据类型。
- 未登录状态是否仍可浏览公开内容。
- 个人相关操作是否在需要时触发登录。
- 页面是否继续符合本文件的品牌色、间距和布局原则。

如果实现与本文件冲突，应先更新设计、PRD 和变更记录并获得确认，之后再修改代码。
