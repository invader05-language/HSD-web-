# 成员与管理员登录访问设计

- 日期：2026-08-03
- 状态：已确认，前端 Mock 已实施；后端待接入
- 范围：Nuxt 前端 Mock 原型；不接入后端、数据库或真实密码服务。

## 目标

在共享 `/login` 页面提供“成员登录”和“管理员登录”两种入口模式。两种模式使用同一账号体系；模式仅表达进入成员空间或管理台的意图，权限只能由账号配置决定。

## 账号与权限模型

每个账号关联一名成员档案，并具有以下管理级别之一：

- `member`：仅成员端访问。
- `admin`：可处理全部平台事务，但不能配置管理员账号。
- `owner`：联盟总负责人，可处理全部平台事务并配置管理员账号。

不存在第三种“联盟总负责人登录”模式，也不再维护角色、业务域、数据范围或动作级权限矩阵。

## 登录与续接

- `/login` 默认成员模式，成员模式成功后进入安全的成员续接地址或 `/member`。
- 未登录访问 `/admin/**` 时，自动进入 `/login?mode=admin&redirect=...`。
- 旧的 `/login?redirect=/admin/...` 自动推导为管理员模式，保持兼容。
- 管理员模式只接受启用的 `admin` 或 `owner` 账号；普通成员得到清晰错误提示，不建立管理会话。
- 管理目标中切换到成员模式时，登录后进入 `/member`；切回管理员模式时恢复原安全管理目标。
- 管理员账号也可以在成员模式下进入成员空间。

## 管理端规则

- `admin` 与 `owner` 都可访问所有当前已启用的常规管理模块；操作日志和回收站本次上线不出现在导航且旧地址受上线开关保护。
- 仅 `owner` 可以访问 `/admin/accounts`，并执行授予、撤销、启用或停用管理员资格。
- `admin` 访问管理员账号页或旧角色权限地址时进入权限不足页。
- 原 `/admin/roles` UI、导航、角色数据、权限矩阵和自定义角色功能全部移除；`owner` 访问旧地址重定向到 `/admin/accounts`。
- 联盟总负责人账号不可被降级、停用或撤销管理员资格。
- 管理员资格变更立即影响后续登录、导航和路由访问；不影响成员端身份。

## 管理员账号页面

管理员账号页改为“管理员资格配置”，显示管理员姓名、成员账号、管理级别、资格状态、配置人、配置时间和最近登录。联盟总负责人可以从成员账号中授予或撤销“平台管理员”资格，或启用、停用资格。每项变更都需要确认并保留在当前 Mock 会话的资格变更记录中；本次上线不承诺通过独立操作日志页面查看。

## 视觉与无障碍

保留既有左右分栏登录页、品牌颜色和响应式结构。登录模式使用语义化单选分段控件，保留键盘选择与焦点状态。左侧说明、标题、按钮文案随模式变化；移动端首屏必须同时容纳模式选择和表单开头。

## 安全边界

前端权限仅用于原型中的导航与体验。后端接入后，登录、管理员配置、每个管理读取和写入 API 必须独立验证身份与管理员资格。

## 验收

1. 两种登录模式、旧管理续接地址和安全重定向均正确工作。
2. 普通成员不能通过模式切换或直接 URL 进入管理端。
3. `admin` 可处理常规管理事务，但看不到且无法访问管理员资格配置。
4. `owner` 可以变更下属管理员资格，且不能修改自身负责人资格。
5. 角色权限页面和入口从界面中移除，旧地址按权限兼容。
6. 管理员资格变更同步影响登录、导航、路由和权限不足页面。
