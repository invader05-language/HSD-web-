# 管理员候选项展示与弹窗间距设计

- 日期：2026-08-03
- 状态：已确认，待实施
- 范围：管理员资格配置页的候选用户展示与负责人弹窗布局；不修改权限模型、候选筛选规则或持久化逻辑。

## 目标

让“添加管理员”和“增设联盟总负责人”弹窗中的平台用户候选项更适合快速扫描，并使两个弹窗的底部操作区保持一致的视觉间距。

## 展示设计

候选项统一采用从左到右的三列布局：

| 列 | 内容 |
| --- | --- |
| 姓名 | 成员档案姓名 |
| 归属 | 成员所属中心 |
| 身份 | 管理员显示具体中心负责人名称；普通账号显示“普通成员” |

候选项不再显示登录账号、成员编号或重复的内部标识。当前已配置管理员仍然是可选平台用户，重新选择后只更新其中心负责人管理级别。

## 布局设计

候选列表保持现有容器、边框、选中态和滚动行为。负责人弹窗的底部“取消 / 确认添加”操作区增加与“添加管理员”弹窗一致的上间距；管理员弹窗现有的管理级别选择和操作区不改变。

## 数据映射

- 姓名来自 `MockAccount.name`。
- 归属与成员身份来自账号关联的成员档案。
- 管理员身份来自 `getAdminQualificationLabel`，普通账号回退为“普通成员”。
- 找不到成员档案时使用稳定的空值回退，不影响候选项选择与提交。

## 验收

1. 两个弹窗的候选项均只呈现“姓名、归属、身份”三列。
2. 普通账号身份显示“普通成员”，已配置管理员显示对应中心负责人名称。
3. 候选项仍支持搜索、键盘聚焦、选中态和已有管理员重新绑定。
4. 负责人弹窗底部操作区与管理员弹窗保持相同的视觉间距。
5. 权限边界、候选资格、持久化和审计行为保持现状。
