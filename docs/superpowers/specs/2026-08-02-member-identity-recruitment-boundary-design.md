# 当前人员身份与招新报名数据边界

日期：2026-08-02
状态：已确认并实现前端 Mock

## 目标

解决多账号接入前的双 ID 风险，并确保 26 级预备成员报名不会覆盖正式成员、核心人员或公开成员数据。

## 身份来源

- `sessionStore.currentMemberId` 是当前登录人员 ID 的唯一权威来源。
- 成员档案 Store 只维护 `profiles[id]`，不保存第二个当前人员 ID，也不提供隐式 `currentMember`。
- Header、成员空间、个人资料、报名和结果页面统一通过当前人员 composable，按会话 ID 查询档案。
- 结果中心使用同一人员 ID 选择结果：正式成员读取正式结果，预备成员结合本人的报名记录生成无申请或待公布状态，不复用其他人员结果。
- 后端接入时区分账号 `accountId` 与人员档案 `personId`；前端的 `currentMemberId` 对应 `personId`。

## 演示账号

- `demo-member` → `member-lin`：正式成员，允许投射到已有公开人员和正式成员管理记录。
- `demo-applicant` → `applicant-chen`：预备成员，用于招新报名，不具备公开人员 ID 和正式中心关系。

## 报名与公开数据边界

- 只有预备成员账号可以提交招新报名。
- 报名提交只更新当前预备人员档案及其招新申请，不修改 `member-lin` 或其他正式成员。
- 公开人员、核心人员、中心正式成员和正式成员管理列表只接受具备正式身份与公开人员 ID 的档案。
- 预备成员仅在本人个人中心、个人资料、报名记录及招新管理域中可见。
- 普通中心面试通过或白泽第三轮通过后，后端才建立正式成员关系并生成公开人员关联；该事务不在当前 Mock 中模拟。

## 头像规则

- 上传头像后自动用于公开成员展示，不提供“是否公开头像”开关。
- 上传入口必须提前提示自动公开规则。
- 未上传或移除头像时使用白底 HSD 默认头像。
- `avatarVisible` 是根据 `avatarUrl` 自动计算的输出状态，不是持久化的用户偏好。
- 预备成员即使上传头像，在正式录取前也不会进入公开成员目录。

## 验收标准

1. 切换 `demo-member` 与 `demo-applicant` 后，所有个人页面展示与会话 ID 对应的同一人员资料。
2. 成员档案 Store 不存在 `currentMemberId` 或隐式 `currentMember`。
3. 预备成员提交报名并修改姓名、方向、简介或头像后，`member-lin` 档案保持不变。
4. 预备成员不会出现在公开人员、核心人员、中心正式成员或正式成员管理列表。
5. 正式成员上传头像后公开投射自动显示该头像，移除后恢复默认 HSD 头像。
6. 预备成员未报名时结果中心显示无本期申请，提交后显示待公布，不得显示正式成员的白泽录取结果。
7. 单元测试、TypeScript 检查、Nuxt 生产构建和 Playwright 端到端测试全部通过；GitHub Actions 执行相同检查。
