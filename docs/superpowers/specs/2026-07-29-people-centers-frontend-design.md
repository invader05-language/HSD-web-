# 核心人员、成员风采与四大中心前端增量设计

日期：2026-07-29  
状态：已获用户批准，可实施

## 1. 目标

在不接入后端和数据库的前提下，把部落介绍页中的核心人员、成员风采和四大中心从“首页展示模块”补全为可浏览的公开内容体系：

- 核心人员重点展示区保留，并增加“查看全体核心人员”入口。
- 成员风采区保留，并增加“查看所有成员”入口。
- 四大中心的每张卡片均可点击并进入对应详情页。
- 全部新增页面保持现有深红、近黑、暖白的桌面 Web 设计基调。
- 所有内容默认公开；本阶段不实现个人资料编辑、考核结果等登录后功能。

## 2. 技术边界

- 框架：Nuxt 4、Vue 3、TypeScript。
- 状态：Pinia 继续用于现有登录会话；公开名录不放入全局状态。
- 数据：使用 `app/data/` 下的 TypeScript 结构化数据，页面不得自行重复定义人员或中心数组。
- 后端：本阶段不新增 Nitro API、数据库、ORM 或管理后台。
- 图片：上传头像后自动显示头像；没有上传或已移除时统一显示白底 `< HSD >` 默认头像。

## 3. 信息架构与路由

| 路由 | 页面 | 内容 |
| --- | --- | --- |
| `/about` | 部落介绍 | 核心人员精选、成员精选及两个“查看全部”入口 |
| `/people/core` | 全体核心人员 | 核心人员公开名录、职责和关注方向 |
| `/people/members` | 全体成员 | 可筛选的公开成员风采名录 |
| `/centers` | 四大中心总览 | 四个中心的可点击总览列表 |
| `/centers/:slug` | 中心详情 | 中心使命、方向、工作方式、参与路径和相关成员 |

中心 slug 固定为：

- `baize-development`
- `new-media`
- `tuowei-planning`
- `talent-development`

## 4. 数据模型

### 4.1 人员

`PublicPerson` 包含：

- `id`：稳定标识。
- `name`：公开展示名。
- `role`：岗位或成员角色。
- `centerSlug`、`centerName`：所属中心。
- `direction`：公开方向。
- `bio`：一至两句公开介绍。
- `avatarUrl?`：头像地址。
- `avatarVisible`：由 `avatarUrl` 是否存在自动推导的展示状态，不是用户可编辑的公开开关。
- `isCore`：是否属于核心人员。
- `order`：排序值。

页面只能在 `avatarVisible === true` 且 `avatarUrl` 存在时向 `HsdAvatar` 传入图片，否则由组件显示统一默认头像；上传头像后该状态自动变为 `true`，移除后自动变为 `false`。

### 4.2 中心

`CenterProfile` 包含：

- 总览字段：`slug`、`index`、`title`、`role`、`description`、`topics`。
- 详情字段：`eyebrow`、`headline`、`mission`、`responsibilities`、`learningPath`、`collaboration`、`joinHint`。

## 5. 页面设计

### 5.1 全体核心人员

- 使用暖白底和强标题，延续部落介绍页的 Core Team 区域。
- 顶部说明核心人员的展示标准，不把“核心”解释为成员等级。
- 名录采用三列桌面栅格，卡片包含编号、头像、职责、姓名、方向和简介。
- 未上传或移除头像时仍保持完整布局，不出现随机图片。

### 5.2 全体成员

- 使用冷浅灰信息页背景，强调“公开风采而非个人档案”。
- 提供中心筛选和姓名/方向搜索；筛选状态留在页面本地，不使用 Pinia。
- 桌面端使用两列横向人物条目，避免密集头像墙。
- 空结果显示明确提示和“清除筛选”操作。

### 5.3 中心详情

- 详情页使用现有 `PageBanner`，每个中心以相同骨架承载不同内容。
- 主体依次展示中心使命、主要方向、参与后会做什么、成长路径、协作方式和相关成员。
- 页面底部提供“查看其他中心”和“加入我们”入口。
- slug 不存在时抛出 Nuxt 404。

## 6. 交互与可访问性

- 所有整卡链接在非悬停状态下也必须看得出可点击，并有文字动作提示。
- 链接、筛选按钮和输入框具有键盘焦点状态。
- 桌面正文不小于 16px，触控目标最小 44px。
- 页面在 1440px 桌面端无横向溢出，并延续已有响应式重排。
- 访客查看公开成员与中心详情无需登录。

## 7. 验收标准

- `/about` 同时出现“查看全体核心人员”和“查看所有成员”入口。
- 两个入口分别进入正确的公开名录页。
- `/centers` 的四张中心内容块均可点击。
- 四个中心详情路由均可访问，错误 slug 返回 404。
- 成员筛选可以按中心筛选并按姓名或方向搜索。
- 未上传或移除头像的人员全部使用统一 HSD 默认头像。
- 单元测试、Nuxt 构建和桌面 Playwright 测试通过。
- PRD、README 和变更记录与页面实现保持一致。
