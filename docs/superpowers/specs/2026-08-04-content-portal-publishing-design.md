# HSD 内容与门户发布链路设计规格

- 日期：2026-08-04
- 状态：已确认，待实施
- 技术范围：Nuxt 4 / Vue 3 / Pinia 前端 Mock；生产后端待接入
- 后端需求契约：`docs/backend-requirements/HSD-BE-PORTAL-001-content-automation.md`

## 1. 决策摘要

采用“业务领域 + 门户发布投影”架构：项目、活动、招新批次、成员、画廊和资源继续由各自业务模块维护事实；内容模块维护官网独立内容；门户模块只维护已发布内容的引用、顺序和页面主视觉。

本轮确认：

1. 管理端“内容与门户”只保留“官网内容”和“门户配置”。
2. “首页配置”和“Banner 配置”合并为“门户配置”。
3. 用户端“活动中心”改为“动态与活动”，继续使用 `/activities`。
4. `/activities` 聚合活动、新闻和公开公告，但活动和内容继续使用独立领域模型和详情路由。
5. 用户端和管理端帮助中心均暂时停用，通过统一功能开关隐藏入口并处理旧路由。
6. 普通管理员创建、编辑和提交审核；联盟总负责人审核、发布和下架。
7. 门户配置先保存草稿，由联盟总负责人整份发布；发布前用户端继续读取旧版本。
8. 首页引用失效后，自动选择同推荐位、同内容类型中最新且未被占用的已发布内容补位；没有候选时留空并告警。
9. HSD 快讯支持管理员手动创建，也支持业务事件自动生成草稿；任何自动草稿都必须人工审核后才能发布。
10. 本阶段不接入微信公众号接口，不抓取或迁移公众号文章，也不接入大模型摘要。

## 2. 现状问题

当前“内容与门户”仍是静态原型：

- `app/data/admin-content.ts` 与 `app/data/home.ts` 是两套互不关联的数据源。
- 内容编辑器只修改组件内副本，刷新后丢失，也不会改变用户端。
- “新建内容”“配置首页内容”“预览官网首页”“替换”“选择”和 Banner 编辑等按钮存在无响应或仅更新页面布尔值的情况。
- 内容状态缺少工作台已经使用的“待发布”阶段。
- 项目、活动、画廊和资源在管理端与用户端存在重复静态记录。
- `/activities` 当前只展示活动，首页“查看全部动态”却跳转到该页面，新闻没有稳定聚合入口。
- 帮助中心文案已与登录、招新批次、身份及头像隐私规则不一致。

本次不能通过逐个补按钮解决；必须先建立唯一状态源、发布投影和跨模块引用关系。

## 3. 范围

### 3.1 本轮实现

- 官网内容列表、创建、编辑、预览、审核、发布和下架。
- HSD 快讯、新闻、公开公告三类内容。
- “动态与活动”聚合页以及新闻/公告详情页。
- 门户配置草稿、预览、整份发布、推荐位选择和排序。
- 首页及“加入我们”等预定义页面主视觉配置。
- 业务事件生成 HSD 快讯草稿的前端 Mock 链路。
- 帮助中心功能开关、入口清理和旧路由处理。
- 工作台内容指标、筛选参数和快捷创建入口与真实内容状态联动。

### 3.2 明确不做

- 后端、数据库、消息队列、定时任务和真实跨设备持久化。
- 微信公众号接口、文章抓取、正文迁移和双向同步。
- 大模型生成标题、摘要或正文。
- 通用富文本 HTML 编辑器；首版使用安全的结构化内容块。
- 任意页面 Banner 创建；只管理预定义视觉位。
- 帮助中心内容管理与用户端帮助页。
- 新增内容管理员、自定义角色或权限矩阵。

## 4. 信息架构

### 4.1 管理端

“内容与门户”导航调整为：

1. 官网内容：`/admin/content`
2. 门户配置：`/admin/content/home`

旧地址：

- `/admin/content/banners` 重定向到 `/admin/content/home?view=visuals`。
- `/admin/content/help` 在 `helpCenter: false` 时重定向到 `/admin/content`，并显示一次“当前版本暂未开放”。

内容编辑使用完整工作页，不继续复用只包含标题和摘要的通用抽屉：

- `/admin/content/new`
- `/admin/content/:id`
- `/admin/content/:id/preview`

### 4.2 用户端

- 主导航“活动中心”改名为“动态与活动”，地址保持 `/activities`。
- `/activities` 提供“全部动态、活动、新闻、公告”四个标签视图。
- 活动详情保持 `/activities/:slug`。
- 新闻与公告详情使用 `/updates/:slug`，但不新增顶部导航入口。
- 首页“查看全部动态”继续跳转 `/activities`。
- `/help` 在 `helpCenter: false` 时重定向 `/` 并显示一次“当前版本暂未开放”。

所有指向帮助中心的链接必须移除。登录页改为直接展示：“无法登录或忘记账号时，请联系联盟总负责人核验身份并处理账号问题。”具体联系方式不写死在页面中。

## 5. 领域边界

### 5.1 业务事实由所属模块维护

| 数据 | 唯一维护模块 | 门户允许的操作 |
| --- | --- | --- |
| 招新开放状态、时间、开放中心 | 招新批次 | 读取公开投影，不能覆盖 |
| 活动时间、名额、报名状态 | 活动管理 | 选择推荐、排序 |
| 项目成员、成果、公开状态 | 项目管理 | 选择推荐、排序 |
| 画廊专题与素材 | 画廊/媒体库 | 选择推荐和主视觉 |
| 资源权限、文件状态 | 学习资料 | 选择推荐、排序 |
| 成员人数、中心和身份 | 成员仓库 | 自动统计，不能手填 |
| 新闻、公告、HSD 快讯 | 官网内容 | 创建、审核和发布 |

门户不得保存上述业务记录的可编辑副本。推荐位只保存 `{ entityType, sourceId }` 引用和排序信息。

### 5.2 发布目录

新增统一 `PublishedPortalCatalog` 查询边界，把各领域的公开投影转换为统一候选项：

```ts
interface PortalCatalogItem {
  entityType: "flash" | "article" | "notice" | "project" | "activity" | "gallery" | "resource";
  sourceId: string;
  title: string;
  summary: string;
  to: string;
  publishedAt: string;
  eligibleSlots: PortalSlotId[];
  available: boolean;
}
```

聚合层只能读取已发布且当前可访问的记录。领域模块未完成真实管理链路前，可以通过只读适配器提供现有公开 fixture，但不得声称管理端编辑已经同步。

## 6. 官网内容模型

### 6.1 内容类型

- `flash`：短标题、标签、目标链接、可选失效时间；不生成独立正文页。
- `article`：新闻文章，包含摘要、正文内容块、封面和作者。
- `notice`：公开公告，字段与文章相同，但使用公告展示语义。

预留但本轮不启用：

```ts
originType?: "manual" | "system-event" | "wechat";
originUrl?: string;
externalId?: string;
```

本轮 UI 只使用 `manual` 和 `system-event`。不得展示微信公众号同步入口。

### 6.2 版本与状态

状态链路固定为：

```text
草稿 -> 待审核 -> 待发布 -> 已发布 -> 已下架
               -> 退回草稿
```

- 保存草稿不会改变用户端。
- 待审核由联盟总负责人检查；退回必须填写原因。
- 审核通过进入待发布，仍不会改变用户端。
- 发布必须二次确认并记录发布人、发布时间和版本。
- 下架立即停止公开，必须填写原因。
- 已发布内容再次编辑时生成新的工作版本；用户端继续显示上一个已发布版本。
- 不提供硬删除和回收站；已下架记录可重新创建工作版本。

### 6.3 内容块

首版正文使用结构化块：

```ts
type ContentBlock =
  | { type: "heading"; text: string }
  | { type: "paragraph"; text: string }
  | { type: "image"; assetId: string; alt: string; caption?: string };
```

只允许选择媒体库中处理完成且审核通过的素材。渲染器不接受任意脚本、iframe 或未清洗 HTML。

## 7. HSD 快讯自动草稿

### 7.1 触发事件

本轮至少支持：

- `recruitment.batch.opened`
- `activity.registration.opened`

事件生成的是草稿，不是已发布内容。草稿包含系统建议标题、标签、站内目标、来源说明和可选失效时间。

示例：

```text
事件：recruitment.batch.opened
标题：2026 秋季招新报名已开放
目标：/join
失效时间：批次报名截止时间
来源：system-event / recruitment-batch / batch-current
```

### 7.2 当前前端 Mock

当前没有后端，前端通过独立 `PortalAutomationService` Mock 生成草稿：

1. 批次或活动 Store 的写操作成功后调用 Mock 服务。
2. Mock 服务按幂等键检查是否已生成。
3. 未生成时调用内容仓库的 `createSystemDraft`。
4. 页面只读取内容仓库，不监听页面访问生成数据。

如果业务写入已经成功、但 Mock 自动草稿创建失败，不回滚已经完成的批次或活动操作；管理端显示“快讯草稿生成失败”并提供按同一幂等键重试的入口。

幂等键固定为：

```text
sourceDomain + sourceId + eventType + sourceVersion
```

不得在页面挂载、查询列表、计算 `currentOpenBatch` 或用户访问 `/join` 时生成草稿。

### 7.3 生产后端

生产环境必须由后端在业务写入成功后产生事件并创建草稿。完整要求见 `docs/backend-requirements/HSD-BE-PORTAL-001-content-automation.md`。前端 Mock 不是生产实现，也不能作为后端可以省略的依据。

## 8. 门户配置

### 8.1 首页推荐位

固定推荐位及容量继续由前端设计基线控制：

- HSD 快讯：1 条
- 推荐新闻：3 条
- 精选项目：4 条
- 近期活动：3 条
- 媒体专题：1 条
- 推荐资源：3 条

管理员只能从对应推荐位允许的已发布候选项中选择。配置支持替换、移除、上移和下移；拖拽可以作为增强，但所有操作必须支持键盘。

### 8.2 草稿与整份发布

- 普通管理员保存门户配置草稿和预览。
- 用户端始终读取最近一次已发布配置。
- 联盟总负责人二次确认后整份发布首页配置。
- 发布校验容量、重复引用、候选有效性和素材状态。
- 发布失败不得出现部分推荐位已更新的状态。

### 8.3 失效引用与自动补位

内容下架、活动关闭或资源不可用时：

1. 用户端立即排除失效引用。
2. 系统在同一推荐位、同一内容类型中，按 `publishedAt` 从新到旧选择未被其他位置占用的可用记录补位。
3. 没有候选时该位置留空。
4. 管理端显示失效来源、自动补位结果和待重新发布提示。
5. 自动补位属于运行时公开投影，不修改管理员保存的配置草稿；下一次发布前必须明确确认新的引用。

### 8.4 页面主视觉

“Banner 配置”并入门户配置的“页面主视觉”视图。首批只开放：

- 官网首页主视觉
- “加入我们”主视觉

每个视觉位可以配置已审核素材、替代文本和辅助文案。业务 CTA 保持代码和业务状态控制：招新按钮是否可用只由招新批次决定，门户配置不能将关闭批次强制改为可报名。

## 9. 动态与活动

`/activities` 使用统一时间线视图，但不合并领域模型：

- “全部动态”按公开时间倒序聚合活动、新闻和公告。
- “活动”按活动时间和报名状态展示，进入 `/activities/:slug`。
- “新闻”“公告”按发布时间展示，进入 `/updates/:slug`。
- HSD 快讯主要展示在首页，不增加独立详情；目标可以指向上述任一站内页面。
- 下架内容、未发布内容和不可公开的业务记录不能进入聚合页。

## 10. 权限与审计

| 操作 | 普通管理员 | 联盟总负责人 |
| --- | --- | --- |
| 创建、编辑、保存草稿 | 允许 | 允许 |
| 提交审核、预览 | 允许 | 允许 |
| 退回、审核通过 | 不允许 | 允许 |
| 发布、下架 | 不允许 | 允许 |
| 保存门户草稿 | 允许 | 允许 |
| 发布门户配置 | 不允许 | 允许 |

前端权限只服务当前 Mock 体验。后端必须对每个读取、写入、审核、发布和下架接口独立鉴权。

内容和门户模块保存自己的领域审计记录，不依赖当前关闭的全局操作日志页面。审计至少包含操作者、动作、对象、前后版本、原因和实际时间。

## 11. 帮助中心停用

统一发布配置新增：

```ts
helpCenter: false
```

该配置必须同时控制：

- 管理导航和用户端入口。
- `/admin/content/help` 与 `/help` 路由。
- 页脚、首页、登录、加入我们等关联链接。
- 自动化测试的可访问性预期。

旧文件和未来数据契约可以保留，但本次 UI 不得继续依赖帮助页面。旧路由重定向后显示一次“当前版本暂未开放”，不得形成循环。

## 12. 前端架构

建议边界：

- `app/types/portal-content.ts`：内容、版本、状态和审计类型。
- `app/types/portal-config.ts`：推荐位、主视觉和发布配置类型。
- `app/stores/portal-content.ts`：版本化内容 Mock 仓库。
- `app/stores/portal-config.ts`：门户草稿和已发布配置。
- `app/services/portal-automation.mock.ts`：业务事件生成快讯草稿。
- `app/composables/usePublishedPortal.ts`：用户端只读发布投影。
- `app/composables/usePortalCatalog.ts`：跨领域公开候选目录。

Pinia Store 使用带 schema 版本的 `localStorage` Mock 持久化。页面不得直接修改 fixture；未来后端接入时由服务适配器替换 Mock 存储。

## 13. 错误处理

必须覆盖：

- 重复 slug、空标题、缺少目标、无效内容块。
- 非法状态跳转和权限不足。
- 版本冲突、存储不可用和持久化失败。
- 失效素材、失效来源和重复推荐。
- 自动草稿重复事件。
- 门户整份发布中的任一校验失败。

失败时保留用户草稿并显示可执行原因；不得只显示“操作失败”。发布和下架失败不能改变用户端投影。

## 14. 迁移策略

1. 将现有 HSD 快讯、新闻和公告 fixture 迁移为内容仓库种子。
2. 帮助文章不迁移到启用数据，只保留关闭状态和旧路由兼容。
3. 首页静态 `FLASH_NEWS`、`NEWS` 等逐个替换为发布投影。
4. 项目、活动、画廊和资源先提供只读公开目录适配器，再由各自模块后续替换为真实仓库。
5. 删除用户端对管理端 fixture 的任何直接依赖。
6. 工作台指标和快捷入口改为读取内容 Store，并真实响应 `status`、`create` 查询参数。

迁移不得长期保留双写或双读；每个领域完成切换后删除对应旧静态源。

## 15. 验收标准

### 15.1 单元与集成

- 状态机不能从草稿跳过审核直接发布。
- 已发布内容编辑不会提前改变用户端。
- 自动事件重复到达只生成一条快讯草稿。
- 普通管理员不能审核、发布或下架。
- 门户配置失败时用户端保持上一发布版本。
- 失效引用按确认规则自动补位且不会跨内容类型。
- 帮助中心开关同时关闭导航、入口和路由。

### 15.2 E2E

- 管理员新建新闻、保存、刷新、重新打开后草稿仍存在。
- 联盟总负责人审核发布后，新闻出现在 `/activities` 并可打开详情。
- 批次开放后只生成快讯草稿；审核发布后首页才显示。
- 门户草稿预览不影响公开首页；整份发布后顺序同步变化。
- 下架首页内容后自动补位，没有候选时不出现死链。
- `/help` 和 `/admin/content/help` 按规则重定向。
- 1440px、390px 和键盘操作无重叠、溢出或不可达控件。

当前浏览器环境曾出现 Chrome `SIGABRT` 和 Playwright bundled Chromium 缺失，正式完成声明前必须重新验证，不能将环境阻塞记为通过。

## 16. 后端交接要求

后端同事或后端 AI 开始工作前，必须读取：

1. 本规格。
2. `docs/backend-requirements/HSD-BE-PORTAL-001-content-automation.md`。
3. 招新批次、活动、管理员资格和发布状态的最新领域规格。

实现后端时不得照搬 Pinia 或 `localStorage` 结构作为数据库设计。前端 Mock 仅用于验证行为，生产端以领域命令、事务、幂等事件、权限和审计契约为准。
