# 内容模块直接上传与素材审阅设计

- 状态：方案已确认，待实施
- 范围：画廊、活动和项目在各自编辑页直接上传、审阅和发布素材
- 业务决定：管理端不再要求先进入“媒体素材库”选择素材

## 1. 决策

画廊、活动、项目展示等内容在各自的新建/编辑页直接添加图片或视频。管理员只管理当前内容关联的素材，不需要在独立媒体素材库和内容编辑页之间往返。

后端仍保留通用上传服务、对象存储和媒体文件记录，但这些是基础设施，不作为管理员必须访问的业务模块。当前原型不把 `/admin/media` 作为画廊发布前置条件。

默认每个素材归属于当前内容，不跨画廊、活动和项目直接复用。后端可以通过文件哈希做内部去重，但不向管理员暴露素材库选择流程。

## 2. 共用上传与审阅工作区

所有内容编辑页复用 `ContentMediaUploader`，但按内容类型显示不同的素材形态。组件不只是文件选择按钮，必须提供管理员在发布前审阅素材的完整工作区：

- 顶部拖放区和“添加图片/视频”按钮，明确可接受格式、数量与大小限制。
- 上传队列显示 `uploading`、`processing`、`ready`、`failed`；失败项保留错误原因并可重试或移除。
- 已上传素材以缩略图网格呈现；视频显示封面和类型标记。管理员可点击查看大图/视频预览、删除和调整顺序。
- 选中单个素材后可编辑标题、说明、替代文本和画面比例；替代文本用于用户端无障碍描述。
- 编辑器内提供接近用户端布局的预览区，明确展示封面、详情素材的排列及未完成素材的状态。

封面只接受图片；详情素材和画廊专题允许图片或视频。默认限制为图片 `JPEG/PNG/WebP`、单文件不超过 10 MB，视频 `MP4/WebM`、单文件不超过 200 MB；前端先做提示和拦截，真实后端再次校验并可通过配置调整。

原始文件不写入 `localStorage`。前端 Mock 将 Blob 写入 IndexedDB，只在 Store 中保存 `localBlobId` 和附件元数据；页面加载时重新生成临时对象 URL，并在组件卸载后释放。这样保存草稿后刷新仍能审阅素材，也不会把大段 Data URL 塞进浏览器存储。后端接入后，上传适配器改为返回 `mediaId`、真实 URL、缩略图和处理状态，编辑器契约保持不变。

## 3. 画廊工作流

管理端路由调整为：

- `/admin/gallery`：画廊专题列表、状态和操作入口
- `/admin/gallery/new`：新建画廊专题
- `/admin/gallery/[id]`：编辑已有画廊专题

新建/编辑页共用 `GalleryEditor`。编辑器提供标题、分类、年份、摘要、制作团队、归属中心和直接上传素材等字段，不再显示 Slug，也不再显示“选择可用媒体素材”的媒体库复选框。

画廊使用“多素材专题”模式：至少一项完成处理的素材；所有已选素材可排序，并在用户端专题详情内按顺序渲染。第一项素材同时作为专题列表封面，编辑器中必须明确提示。专题编辑器展示标题、分类、年份、摘要、制作团队、归属中心和专题素材；不显示 Slug，也不显示“选择可用媒体素材”的素材库复选框。

制作团队字段继续保留。用户端 `/gallery/[slug]` 已展示该字段，发布快照更新后用户端同步渲染。

## 4. 活动工作流

活动编辑器新增“活动视觉”区域，采用已确认的“**一张必填封面 + 多张可选详情素材**”模式：

- 封面素材独立于详情素材，在编辑器顶部或基本信息后显示固定图片槽位；缺少封面时可以保存草稿，但不能直接发布。
- 详情素材复用多素材上传与审阅界面，供活动详情页展示活动场景、议程补充或往期照片；可为空。
- 用户端 `/activities` 的卡片读取已发布封面，`/activities/[slug]` 读取封面及已发布详情素材；草稿和后续修改不会提前影响公开页。
- 直接发布必须同时满足活动现有必填业务字段、封面 `ready`、全部已添加素材均 `ready`，以及所有已添加素材具有替代文本。

## 5. 项目工作流

项目不能只在现有 `/admin/projects` 静态工作台添加上传按钮。本轮方案要求补齐与活动、画廊同等的闭环：

```text
/admin/projects（列表、状态、入口）
  -> /admin/projects/new（新建项目草稿）
  -> /admin/projects/[id]（编辑已有项目）
  -> useProjectsStore（草稿、权限、发布快照）
  -> /projects 与 /projects/[slug]（只读取公开投影）
```

项目采用同样的“**一张必填封面 + 多张可选详情素材**”模式：

- 项目封面用于用户端项目列表、首页推荐卡片和详情页首屏；未完成封面时禁止发布。
- 详情素材用于项目详情中的成果、过程或现场记录，支持排序和逐项无障碍说明；可为空。
- `ProjectEditor` 负责项目基础信息、中心归属、成员/协作信息、项目内容和素材；`useProjectsStore` 负责草稿保存、中心范围权限、Slug 生成和 `publishedSnapshot`。
- 现有 `PROJECT_DETAILS`、`PROJECTS` 和 `ADMIN_PROJECT_RECORDS` 仅作为旧静态样例。改造后应迁移为初始种子或兼容回退，不能继续成为管理端写入与用户端读取的唯一来源。
- 发布成功后才更新 `/projects`、`/projects/[slug]`、门户目录及首页项目槽位；保存草稿和素材变更都不会直接改变用户端。

## 6. 上传与领域数据

抽取通用 `ContentMediaUploader` 组件，负责：

- 选择图片或视频文件
- 显示上传中、处理中、成功和失败状态
- 删除和调整素材顺序
- 编辑标题、说明、替代文本和画面比例
- 只有素材状态为 ready 且替代文本完整时才允许发布

领域层将素材视为内容附件，而不是独立媒体库条目。附件至少包含：

```ts
interface ContentMediaAttachment {
  id: string;
  mediaId?: string;
  localBlobId?: string;
  role: "cover" | "detail";
  kind: "image" | "video";
  title: string;
  caption: string;
  alt: string;
  aspect: "landscape" | "portrait" | "wide";
  sortOrder: number;
  url?: string;
  thumbnailUrl?: string;
  status: "uploading" | "processing" | "ready" | "failed";
  errorMessage?: string;
}
```

当前 Mock 使用上传适配器返回本地预览引用；真实后端接入时，适配器改为上传到对象存储并返回 `mediaId`、状态和公开预览地址，编辑器和领域 Store 的契约保持不变。

画廊附件均为 `detail`；活动和项目必须有且仅有一个 `cover`，可有零至多项 `detail`。封面编辑器只显示预览、替换、移除和替代文本；详情素材才显示标题、说明、替代文本和比例字段。

## 7. 草稿、发布与兼容

草稿可以暂时没有素材或存在未完成字段，保存成功后仍不出现在用户端。直接发布必须校验各内容类型的必填文本字段、归属中心和附件：画廊至少一个 `detail`，活动和项目各一个图片 `cover`。封面必须为 `ready` 且替代文本非空；详情素材可为空，但只要已添加，其标题、说明、替代文本、画面比例必须完整且状态为 `ready`。

发布时生成 `publishedSnapshot`，用户端只读取公开快照。后续素材修改不会自动改变已发布活动、画廊或项目，管理员需要重新编辑并发布。

已有 v1 画廊数据继续保留。旧素材引用在迁移后作为 legacy 附件展示，不再出现在新的媒体库选择器中；新建和编辑产生的素材使用新的内容附件结构，避免历史专题丢失。

## 8. 后端接入边界

活动、画廊和项目都复用 `ContentMediaUploader`，分别把附件归属到当前内容。它们不需要接入独立媒体库页面，也不共享管理员选择列表。

真实后端需要提供通用上传接口、处理状态查询、附件归属校验、发布时状态校验和删除/回收策略。前端将按画廊、活动、项目三个独立实施计划接入相同契约；项目实施先完成自身的草稿和公开投影链路。

用户端统一通过 `ContentMediaView` 渲染附件：优先使用后端 `url`/`thumbnailUrl`，Mock 环境从 `localBlobId` 读取 IndexedDB。活动与项目的封面进入列表和详情；项目封面还进入门户目录和首页项目槽位；画廊列表使用排序后的第一项素材，详情和灯箱同时支持图片与视频。

## 9. 非目标

- 本轮不建设独立媒体素材库管理闭环
- 本轮不实现跨内容复用素材
- 本轮不接入真实对象存储、转码、病毒扫描或 CDN
- 本轮不把媒体库重新包装成隐藏的跨内容素材选择器
- 不把原始大文件、视频二进制或 Data URL 存入浏览器持久化数据
