# 招新考核与门户时间线优化设计

## 目标

修正三组已确认的产品行为：报名窗口开放或暂停时允许管理员录入已有候选人的考核结果；首页在推荐槽位为空时仍能从已发布内容展示快讯与新闻；动态与活动列表使用稳定的活动日期字段并在桌面、平板和手机端保持不重叠。

## 业务边界

- `saveRoundOutcome` 与 `recordAdjustmentDecision` 是候选人级内部命令，批次处于 `open`、`paused` 或 `closed` 时都允许执行。
- 候选人第一次录入轮次结果时锁定报名，后续修改受当前轮次、候选人中心权限和整批发布状态约束。
- `advanceAssessmentRound` 与 `publishBatchResults` 是批次级命令，只有批次有效状态为 `closed` 时允许执行。开放或暂停时页面明确提示“可录入已有候选人，但关闭报名后才能推进轮次或发布结果”。
- 草稿、已归档和已发布结果仍只读；考核保存只写内部 Mock 状态，不改变成员公开身份，整批发布才执行正式成员投影。
- 接受调剂且第一轮不通过的候选人，保存后状态为 `offline-adjustment-pending`；关闭抽屉后重新打开必须恢复“线下调剂结果”字段。调剂决定仍由独立的 `recordAdjustmentDecision` 命令完成。

## 门户投影

- 手动配置的有效引用优先展示。
- `flash` 槽位没有手动引用时，从同一公开目录取最新一条有效快讯。
- `news` 槽位没有手动引用时，从同一公开目录取最新的文章和公告，最多三条；不把活动混入“正在发生的事”。
- 自动回退只发生在运行时，不写入门户草稿；管理端公开配置页显示自动回退提示，提醒负责人后续人工精选。
- 没有任何候选内容时保留模块结构，显示面向访客的简短空状态，不输出“暂无已发布快讯”等内部投影措辞。

## 时间字段与布局

- `PortalCatalogItem.eventAt` 为可选字段，仅活动使用；活动详情的 `date` 映射为 `eventAt`，`publishedAt` 仍表示内容发布时间。
- `/activities` 对活动按 `eventAt` 展示和排序，对新闻/公告按 `publishedAt` 展示和排序。
- 活动列表桌面日期列使用稳定的 `minmax(210px, 230px)` 轨道，内容列允许收缩，日期不换行；平板将操作移至第二行，手机使用单列堆叠。

## 错误与后端交接

- 考核抽屉内直接展示保存错误，避免错误被遮挡在抽屉背后的页面顶部。
- 后端保持两个独立命令：候选人轮次结果写入、线下调剂决定写入；另提供批次级推进和发布接口，并在服务端复用上述 `open | paused | closed` 与 `closed-only` 门禁。
- `eventAt`、`publishedAt`、`assessmentStartedAt` 和审计记录均保留为独立字段，后端不得用内容发布时间替代活动发生时间。

## 回归范围

更新单元与 Playwright 回归用例，覆盖开放/暂停批次的候选人结果写入、开放批次不能推进/发布、首页自动回退、活动时间语义和响应式不溢出。根据本次执行约定，本地测试命令暂不运行，由 CI 在后续集中验证。
