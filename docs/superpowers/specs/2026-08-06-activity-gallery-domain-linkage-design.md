# 动态与活动、媒体画廊领域联动设计

- 状态：已实施前端闭环，后端待接入
- 技术范围：Nuxt 4 / Vue 3 / Pinia，使用带版本的浏览器 `localStorage` 模拟领域仓库
- 业务规则：活动不限人数、不保留候补；中心管理员与联盟总负责人均可直接发布，中心管理员仅管理所属中心

## 1. 目标

活动和画廊必须各自拥有唯一事实来源，管理端写入的草稿与公开版本分离，用户端只能读取已发布快照。活动报名、管理端审核和用户端状态展示使用同一 `activityId`；画廊专题、素材引用和用户端渲染使用同一 `galleryId`/`slug`。

## 2. 活动闭环

`useActivitiesStore` 维护活动草稿、`publishedSnapshot`、发布状态、报名窗口和报名记录。活动字段保存后只改变草稿；`publish` 才替换公开快照，`unpublish` 从门户目录移除。发布新活动会默认开启不限人数报名。

报名记录状态只有 `registered`、`accepted`、`rejected`、`cancelled`。已登录成员可提交或取消自己的报名；管理员按活动归属中心读取报名，执行录取或不录取，并记录审核人、时间和原因。重复报名会被拒绝，不存在容量满和候补分支。

用户端 `/activities` 和 `/activities/[slug]` 从 Store 的公开投影读取；管理端 `/admin/activities` 只负责列表与状态导航，`/admin/activities/new` 负责新建草稿，`/admin/activities/[id]` 负责编辑已有活动，`/admin/activities/registrations` 负责筛选和审核报名。活动编辑器使用结构化时间选项，草稿可暂存不完整内容，只有直接发布要求所有必填字段完整。

活动详情字段使用“活动内容”语义；持久化版本从 1 升至 2 时，将旧版 `audience` 字段迁移到 `content`，不丢失公开快照和报名记录。

## 3. 画廊闭环

`useGalleryStore` 维护每个画廊专题的草稿和公开快照，支持新建、编辑、发布、下架和按权限列出专题。专题 `slug` 在首次公开后不可修改，避免已发布链接失效。

画廊编辑器只能引用 `ADMIN_ASSETS` 中处理完成且审核通过的图片/视频，媒体素材表仍是只读种子数据，不新增平行 `media-assets` Store。用户端 `/gallery` 和 `/gallery/[slug]` 只渲染公开快照，编辑未发布时不影响现有页面；发布或下架后门户目录和详情路由立即跟随公开状态。

## 4. 权限与持久化

联盟总负责人可管理全部活动和专题；中心管理员通过稳定的 `ownerCenterId` 进行范围校验。Store 使用独立 schema 版本、损坏数据回退种子、写入失败回滚内存变更并暴露 `persistenceError`。后端接入时应将这些命令映射为服务端事务，并在服务端重复鉴权、校验素材状态、保证幂等和保留审计记录。

## 5. 验证

单元测试覆盖草稿/公开快照隔离、权限范围、活动报名重复校验、录取/不录取、不设候补、画廊素材可用性和下架可见性。端到端验证应覆盖公开活动报名登录续接、管理端活动发布与审核、画廊新建/编辑/发布后的用户端渲染，以及中心管理员越权阻断。
