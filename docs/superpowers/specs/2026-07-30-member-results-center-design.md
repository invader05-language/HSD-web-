# 用户端结果中心设计规格

> 本草稿已由后续确认的完整规格取代。个人端实现应以
> [`2026-07-30-recruitment-results-system-design.md`](2026-07-30-recruitment-results-system-design.md)
> 为准；新规格同时包含志愿限制、预备成员、管理端考核台、线下调剂录入和正式成员联动。

日期：2026-07-30
产品：白云 HSD 开发者部落
实现状态：用户端已接入现有主站
范围：Nuxt/Vue 用户端前端；管理端、真实 API 与数据库不在本轮实现范围

## 1. 目标

把现有受保护的“考核结果”占位页升级为主站内的“结果中心”。登录用户在一个页面中查看本人当前有效的招新录取和阶段考核状态，页面不得脱离现有主站单独展示。

## 2. 路由与访问

- 主导航入口改名为“结果中心”，进入 `/member/results`。
- `/member/results` 复用全站登录续接；匿名访问进入 `/login?redirect=%2Fmember%2Fresults`，演示登录后返回结果中心。
- 旧 `/assessment-results` 保留兼容跳转，登录后转到 `/member/results`。
- 成员空间中的原“考核结果”入口改为“结果中心”并进入新页面。

## 3. 页面结构

- 页面使用现有 `SiteHeader`、`SiteFooter`、1240px 内容宽度和品牌令牌。
- 桌面端页头为暖白主信息区与近黑批次信息区。
- 主内容包含“招新录取”和“阶段考核”两个可切换页签。
- 招新录取页签使用左侧结果档案、右侧志愿与负责人信息的双栏结构。
- 阶段考核页签只展示当前有效阶段和结论，不展示完整考核历程。

## 4. 当前 Mock 数据

当前前端使用一条明确标注为演示数据的已录取状态：

- 批次：2026 秋季招新
- 当前身份：正式成员
- 第一志愿：白泽开发中心
- 第二志愿：新媒体中心
- 第三志愿：人才发展中心
- 白泽意向方向：鸿蒙开发
- 接受调剂：是
- 最终归属：白泽开发中心
- 最终方向：鸿蒙开发
- 当前阶段：考核已结束
- 对应负责人：一名白泽开发中心负责人，姓名与联系方式使用演示占位

## 5. 状态与隐私边界

前端内部语义模型覆盖：待公布、已录取、候补、未录取、调剂后录取、无本期申请。调剂决定在线下完成；“调剂后录取”在用户端统一呈现为“已录取”，只展示最终中心，不暴露调剂过程。

页面只展示：

- 当前身份
- 当前阶段
- 当前结论
- 最终归属中心
- 白泽最终方向
- 三个部门志愿
- 白泽意向方向
- 是否接受调剂
- 一名对应负责人及联系方式

页面不展示：

- 完整考核时间轴或调剂过程
- 分数、排名、公开评语和管理员内部备注
- 确认加入或放弃名额
- 报到时间、报到地点和携带材料

## 6. 视觉与交互

- 主要验收视口为 1440×1000，同时保证 1366px 桌面宽度无横向滚动。
- 使用深红 `#B1202B`、近黑 `#211F1E`、暖白 `#F4F0EB`、冷灰 `#F5F6F7`。
- 卡片以边框、背景和间距建立层级，不使用大阴影、渐变或大圆角。
- 页签必须支持鼠标和键盘焦点，状态不能只依赖颜色表达。
- 负责人联系方式复制成功后提供文本反馈。

## 7. 数据接入边界

本轮只提供 TypeScript 前端语义契约和 Mock 数据，不定义数据库表字段，不连接真实成员服务。后续 API 应映射到该语义契约；管理员发布的最新有效结果覆盖页面展示，历史记录保留在管理端而不输出到用户端。
