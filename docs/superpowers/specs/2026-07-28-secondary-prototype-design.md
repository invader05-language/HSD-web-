# 白云 HSD 开发者部落二级页面原型设计

## 1. 目标

建立一个可以通过公开链接访问的桌面端 Web 原型站，让需求方、设计者和开发者能够逐页检查二级页面结构、视觉基调、权限边界与关键交互状态。

原型站是设计交付，不是正式业务系统。它不连接真实数据库、登录服务、报名接口或成员数据。

## 2. 设计基线

- 品牌名称：白云 HSD 开发者部落。
- 设计类型：桌面端 Web。
- 基准宽度：1440px。
- 主要颜色：品牌深红 `#B1202B`、近黑 `#211F1E`、暖白 `#F4F0EB`、冷灰 `#F5F6F7`。
- 视觉方向：校园科技社群、编辑部式排版、真实作品、克制理性、青年行动力。
- 所有正式图片继续使用素材占位，不直接使用用户提供的宣传海报。
- 未确认授权前，不使用华为 Logo、Huawei ICT Academy 标识或官方视觉资产。

## 3. 页面范围

### 3.1 公开内容页面

1. 项目详情：以“智巡先锋”为示例，展示问题、方案、流程、演示、成果、团队和相关项目。
2. 活动详情：以“HarmonyOS 生态技术峰会”为示例，展示时间、地点、名额、流程、须知、FAQ 和报名入口。
3. 新闻详情：展示标题、导语、作者、时间、浏览量、正文目录、图文内容和相关阅读。
4. 中心详情：以“白泽开发中心”为示例，展示使命、方向、数据、项目和加入入口。
5. 媒体相册：展示主题介绍、分类筛选、图片网格和灯箱预览说明。
6. 资源预览：展示资源信息、PDF 在线预览、版本信息、下载权限和相关资源。
7. 成员名册：展示正式成员的头像、姓名、班级、中心和部落职务；上传头像即视为用于公开展示，未上传时使用默认 HSD 头像。
8. 成员故事：展示成员主动公开的成长经历、作品和方向，不展示联系方式、考核结果等私密信息。
9. 联系我们：展示咨询分类、公开联系方式、校园位置和留言表单。

媒体画廊目录每页展示 6 个专题；总页数必须由当前筛选结果数量除以每页数量后向上取整，禁止写死页码。分页按钮、页码、上一页和下一页必须切换真实且不重复的专题数据，首尾页使用禁用状态。切换分类后重新计算总页数并回到第一页；只有一页结果时隐藏分页。

项目、活动、媒体画廊和资源目录统一使用同一分页交互：总页数一律根据当前筛选后的实际条目数和每页条目数动态计算，只有总页数大于 1 时才显示分页；显示出的上一页、页码和下一页必须能够真实切换列表数据，筛选条件变化后统一回到第一页并重新计算页数。不得写死页码，也不得展示永久禁用、没有数据切换能力的装饰性分页按钮。

项目成果列表使用“全部、HarmonyOS、AI 应用、校园服务、软硬件”分类筛选。项目归类以业务定义为准：小白云属于“校园服务”，智能伴侣属于“HarmonyOS”；筛选结果数量与项目卡片必须同步更新。

### 3.2 登录后任务页面

1. 招新申请：包含基本资料、方向选择、经历与期待、确认提交四个步骤。
2. 成员空间概览：展示个人数据摘要、最近进度、下一步、成长路径和近期安排。
3. 资料编辑：本人可以修改姓名、年级、班级、实践方向、个人简介和头像；学号、所属中心、组织职务保持系统只读。头像上传后自动用于正式成员公开展示，不提供独立公开开关。
4. 个人记录：通过标签切换申请进度、考核结果、活动比赛和成长记录。

### 3.3 全局交互状态

1. 按需登录弹窗。
2. 活动报名填写、提交成功、待审核、名额已满和报名截止。
3. 招新申请保存草稿、提交成功和审核进度。
4. 公开资源直接下载、内部资源登录后下载。
5. 相册分类切换和灯箱预览。
6. 成员资料公开范围设置。
7. 个人记录空状态、加载失败和无权限状态。

## 4. 页面组织

二级页面使用混合式组织：

- 新闻、项目、中心、媒体、资源和成员故事使用完整内容页。
- 活动、资源下载和招新等任务在页面内提供明确行动区。
- 登录拦截、轻量确认和操作结果使用弹窗或状态面板。
- 成员空间、资料编辑和个人记录使用独立任务页面。

页面分为三类骨架：

| 类型 | 页面 | 核心结构 |
| --- | --- | --- |
| 内容叙事型 | 新闻、项目、中心、成员故事 | 主标题、内容正文、结构化侧栏、相关推荐 |
| 行动决策型 | 活动、资源、招新 | 关键信息、详细说明、持续可见的行动入口 |
| 个人任务型 | 成员空间、资料编辑、个人记录 | 固定任务导航、个人状态和表单工作区 |

## 5. 权限边界

公开浏览不要求登录：

- 新闻、公告和活动详情
- 四大中心和项目成果
- 媒体作品
- 经授权的成员名册与成员故事
- 公开资源
- 联系方式

只有涉及个人身份、个人数据或个人操作时要求登录：

- 提交或取消活动报名
- 填写招新申请
- 下载内部资源
- 编辑个人资料
- 查看申请进度、考核结果、活动记录和成长记录

登录成功后必须回到原页面并继续原任务，不能丢失上下文。

用户端登录页不得直接展示 `redirect` 的原始路由或查询参数；该参数仅用于内部安全续接，登录成功后仍须返回来源任务。

活动详情页必须读取全站统一会话状态：未登录时，报名入口显示明确的登录提示并携带当前活动及报名参数前往登录页；已登录时，页面同步当前登录信息，全部报名入口显示“立即报名”并直接进入当前活动的报名状态，不得再次要求登录。

结果中心的负责人联系方式在页面中使用脱敏格式展示；点击“复制联系方式”必须复制完整联系值。优先使用浏览器 Clipboard API，在非安全上下文或权限被拒绝时使用兼容降级；只有复制成功后显示“已复制”，失败时明确提示重试。

## 6. 在线原型结构

在线原型采用静态站点实现：

- 首页提供原型说明、页面目录和权限图例。
- 每个页面可以通过目录直接打开。
- 项目成果详情和活动中心详情必须包含在首版部署中。
- 页面内的标签、筛选、弹窗和状态切换使用本地 JavaScript 模拟。
- 所有表单只展示交互效果，不提交或保存真实数据。
- 原型不设置真实注册、登录或找回密码能力。

## 7. 内容与数据

- 使用明确标记的示例内容和素材占位。
- 不上传成员名单、教师或负责人资料。
- 不使用真实手机号、邮箱、学号、考核结果和报名信息。
- 项目、活动和数字信息在正式发布前需要再次确认。

## 8. 异常与空状态

原型至少展示以下状态：

- 报名已截止
- 活动名额已满
- 申请待审核
- 暂无考核结果
- 暂无成长记录
- 内部资源需要登录
- 内容加载失败
- 当前账号无查看权限

每个异常状态必须说明原因和下一步操作，不使用空白页面。

## 9. 验收标准

1. 公开链接可以在无需本地环境的情况下打开。
2. 原型以桌面端 Web 形式展示，不使用移动端画布。
3. 页面目录能够打开本规格列出的全部 13 个页面。
4. 项目详情和活动详情使用此前已经确认的完整展开结构。
5. 所有页面继续使用统一导航、字体层级、色彩和间距系统。
6. 登录只在个人操作发生时触发。
7. 交互按钮能够展示对应弹窗、标签或状态变化。
8. 页面中不出现真实个人敏感数据或未经授权的品牌素材。
9. 原型站清楚标记“设计预览，不是正式业务系统”。
10. 后续页面修改同步更新本规格、PRD、原型和设计变更记录。
11. 已登录用户进入活动详情时，全部报名入口均显示“立即报名”并直达当前活动报名状态；只有未登录用户显示登录提示。
12. 用户端登录页不展示原始跳转路径，但登录后的来源续接保持有效。

## 10. 本轮不包含

- 管理员后台
- 真实用户认证
- 数据库和业务接口
- 文件真实上传或下载
- 微信、QQ 或学校统一身份认证
- 移动端专项设计
- 正式域名、备案和生产内容发布
