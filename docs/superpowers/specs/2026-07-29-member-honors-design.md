# 成员个人荣誉展示设计

日期：2026-07-29  
产品：白云 HSD 开发者部落  
状态：设计已确认，尚未进入前端实现

## 1. 目标

在不破坏成员名录扫描效率的前提下，展示成员主动公开且经过确认的个人荣誉。内部称号、比赛奖项、证书、优秀作品和表彰统一使用“个人荣誉”概念，不在产品界面中拆分类别。

## 2. 推荐方案

采用“成员列表 + 个人详情”的双层展示：

- 成员列表只展示一个重点荣誉。
- 点击成员进入公开个人详情页，查看完整公开荣誉。
- 没有公开荣誉时不显示空标签或“暂无荣誉”。
- 不根据荣誉数量、级别或时间生成公开排行榜。

## 3. 路由

新增公开成员详情路由：

`/people/:id`

核心人员名录和全体成员名录中的成员卡均可进入该路由。未知或不公开的成员 ID 返回 HTTP 404。

## 4. 成员列表

### 4.1 重点荣誉

每位成员最多选择一条重点荣誉用于名录展示。

重点荣誉位于成员姓名和实践方向附近，使用克制的文字标签或单行信息，不使用彩色勋章墙、大面积金色装饰或多枚图标。

示例：

`重点荣誉 · 2026 优秀项目成员`

### 4.2 卡片行为

- 整张成员卡可点击。
- 未 hover 时显示“查看成员详情 →”。
- 键盘可以聚焦并进入详情页。
- 卡片继续展示头像、姓名、所属中心、实践方向和简介。
- 重点荣誉最多占一行，过长文案需要在内容录入阶段缩短，不依赖省略号隐藏关键信息。

### 4.3 无荣誉状态

没有公开荣誉的成员卡保持现有结构，不预留空白标签，不显示占位文案。

## 5. 成员详情页

页面按以下顺序组织：

1. 顶部导航
2. 面包屑
3. 成员头像、姓名、所属中心和实践方向
4. 公开简介
5. 重点荣誉
6. 完整个人荣誉记录
7. 参与项目或公开作品
8. 返回全体成员与所属中心入口
9. 页脚

详情页只展示成员主动公开的内容，不展示联系方式、考核结果、成长记录、申请进度或内部备注。

## 6. 个人荣誉记录

内部称号和外部奖项使用同一套记录。未来数据至少支持：

- 荣誉名称
- 获得时间
- 简短说明
- 是否重点展示
- 是否公开
- 审核状态
- 排序

颁发单位、证明材料和关联项目可作为后端扩展字段，但在字段确定前不进入当前前端 Mock 契约。

## 7. 公开与审核

- 成员可以决定单条荣誉是否公开。
- 只有审核通过且选择公开的荣誉可以进入公开名录和成员详情。
- 每人最多一条荣誉标记为重点展示。
- 取消公开后，公开页面不再输出该记录。
- 证明材料只用于审核，不在公开页面直接展示原文件地址。
- 不公开荣誉的名称、证明材料地址和内部备注不得进入匿名客户端数据。

## 8. 视觉原则

- 个人荣誉是成员信息的一部分，不盖过姓名、方向和真实实践。
- 列表标签使用品牌红小字、细边框或短横线建立层级。
- 详情页使用纵向时间记录或克制的分隔列表，不使用游戏化勋章墙。
- 同一成员荣誉较多时先展示最新记录，并提供展开或分页；不无限延长首屏。
- 核心人员和普通成员使用相同荣誉规则，避免形成两套评价体系。

## 9. 验收标准

- 有重点荣誉的成员卡只显示一条重点荣誉。
- 没有公开荣誉的卡片不显示空状态。
- 成员卡整卡进入 `/people/:id`。
- 成员详情展示全部已公开、审核通过的荣誉。
- 未公开或未审核荣誉不出现在页面、DOM 或匿名客户端数据中。
- 未知成员 ID 返回 404。
- 页面不显示公开排行榜。
- 1440px 桌面布局无横向溢出。
