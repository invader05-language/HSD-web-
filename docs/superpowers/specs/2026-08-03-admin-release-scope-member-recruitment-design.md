# HSD 管理端上线裁剪、报名与成员管理设计规格

- 日期：2026-08-03
- 状态：已确认，前端 Mock 已实施；后端待接入
- 技术范围：Nuxt 4 / Vue 3 / Pinia 前端 Mock
- 主要验收视口：1440px 桌面端、390px 移动端

## 1. 目标

本轮为首次上线收敛暂时不用的管理模块，并补全报名详情、报名名单导出、新成员创建和核心人员添加能力。实现必须延续现有管理端视觉语言，同时保持成员身份、管理员资格、中心负责人和核心人员之间的数据边界。

本轮完成后：

1. 暂未启用的管理模块不再通过导航、按钮或旧地址进入。
2. 每条招新报名记录都有可访问的只读详情页。
3. 当前筛选后的报名名单可以真实导出为 CSV，并为后端 XLSX 导出留下明确契约。
4. 管理员可以直接创建新的正式成员账号。
5. 正式成员的公开展示资料默认公开，不存在公开/非公开开关。
6. 核心人员和中心负责人关系符合联盟规范。
7. 白泽实践方向成为唯一枚举字段，并且只对所属中心为白泽的成员显示。

## 2. 上线功能裁剪

### 2.1 本次关闭

- 操作日志：`/admin/logs`
- 回收站：`/admin/recycle-bin`
- 独立上传任务页：`/admin/uploads`

源文件和未来数据契约可以保留，但本次上线的 UI、导航和业务操作不得依赖这些页面。

### 2.2 本次保留

“招新批次”保持当前页面、导航和交互，不增加、不删除、不停用。报名、考核和结果中心继续使用现有批次概念。

### 2.3 集中功能开关

新增统一的上线功能配置，至少包含：

```text
auditLog: false
recycleBin: false
uploadTasks: false
recruitmentBatches: true
```

管理端导航、关联按钮和旧路由处理必须读取同一配置，禁止在多个页面散落重复布尔值。

### 2.4 联动调整

- 管理端侧边栏移除操作日志、回收站和上传任务。
- `/admin/logs` 和 `/admin/recycle-bin` 跳转 `/admin`。
- `/admin/uploads` 跳转 `/admin/media`。
- 跳转后显示一次“当前版本暂未开放”，不得形成循环跳转。
- 工作台删除“最近操作记录”和“完整日志”入口。
- 登录页删除操作日志、回收站相关能力说明。
- 管理员资格变更确认不再承诺写入可查看的操作日志。
- 媒体素材库删除“查看上传任务”和“移入回收站”。
- 媒体素材上传入口及上传过程中的局部进度提示可以保留。
- 本轮不提供素材删除操作。

用户端不存在这些管理入口，无需删除用户功能。

## 3. 报名人员列表

### 3.1 筛选与排序

保留：

- 姓名或学号搜索。
- 第一志愿筛选。
- 提交时间排序。

删除“报名状态”筛选以及“资料完整/需要补充”等报名状态概念。

原“报名时间”控件改名为“排序”，选项为：

- 最新提交：`submittedAt.desc`
- 最早提交：`submittedAt.asc`

报名数据使用可解析的完整 `submittedAt` 时间，不再使用缺少年份的展示字符串承担排序。

### 3.2 报名详情路由

新增 `/admin/recruitment/applications/[id]`。列表中的“查看报名”必须使用真实链接进入对应记录。

详情页只读展示：

- 姓名、学号。
- 年级、班级。
- 联系方式。
- 个人简介；为空时不渲染空白内容块。
- 第一、第二、第三志愿。
- 白泽实践方向；仅第一志愿为白泽时显示。
- 是否接受调剂。
- 提交时间。

页面不提供内部备注、考核入口、编辑或状态修改。内容卡片随管理内容区铺满：桌面三列、中等宽度两列、移动端单列。不存在的报名 ID 返回明确的 404“报名记录不存在”。

## 4. 报名名单导出

### 4.1 本次实现

“导出当前名单”真实导出当前搜索、第一志愿筛选和排序结果，格式为带 UTF-8 BOM 的 CSV。

列顺序固定为：

1. 姓名
2. 学号
3. 联系方式
4. 第一志愿
5. 第二志愿
6. 第三志愿
7. 白泽方向
8. 是否接受调剂
9. 提交时间

不导出内部备注、考核阶段、考核结果或管理员信息。筛选结果为空时禁用按钮并提示“当前没有可导出的报名人员”。

文件名格式：

`HSD-<批次名称>-报名名单-YYYYMMDD-HHmm.csv`

CSV 生成必须正确处理逗号、双引号和换行，并对以 `=、+、-、@` 开头的单元格进行公式注入防护。

### 4.2 后端 XLSX 契约

代码注释、类型和本规格必须明确：正式后端接入后，将主导出格式升级为 `.xlsx`。后端导出接口需要：

- 接收与列表相同的搜索、第一志愿、排序和批次参数。
- 使用本规格固定的中文表头和列顺序。
- 将提交时间写为真实日期单元格。
- 在服务端重新验证管理员身份和数据范围。
- 生成文件流，不依赖浏览器拼装大量真实数据。
- 保留 CSV 作为轻量兼容格式时，沿用相同字段契约和公式注入防护。

## 5. 正式成员公开规则

所有正式成员的公开展示资料默认公开，不提供公开/非公开交互。

公开字段：

- 姓名。
- 头像；未上传时使用统一默认头像。
- 所属中心。
- 成员职责。
- 白泽实践方向；仅白泽成员。
- 个人简介；选填。

内部字段：

- 学号、班级。
- 联系方式、账号信息。
- 报名内容、考核记录和管理员信息。

预备成员不进入公开成员或核心人员名录。

### 5.1 管理端成员详情身份变更

成员详情页的“当前身份”使用下拉框展示可用变更，右下角保留“保存资料”作为唯一提交入口。本轮只允许“预备成员”转为“正式成员”；正式成员不可直接降级为预备成员，正式成员详情中的身份选择不可操作。

确认保存身份升级时必须复用该成员已有的平台帐号，不创建第二帐号、不修改帐号标识、不重置密码、不改变管理员资格。保存动作通过统一领域动作一次写入正式成员档案，并同步管理端成员投影、中心成员关系和公开成员投影；持久化失败时整体回滚并显示失败状态。

转正后若该成员没有本期报名记录，成员空间的结果中心显示“无本期申请”空状态，不得因为缺少演示结果数据抛出运行时错误。

成员详情中本轮未接入保存链路的学号、年级、中心、成员职责、联系方式、账号状态和公开资料字段均为只读/禁用，避免给出可编辑但不会入库的错误暗示。身份升级成功后才显示确认反馈和公开页面入口；不产生身份变更时不显示“已同步”成功提示。

需要删除：

- `AdminPublicState` 及公开状态筛选。
- 管理端成员列表的“公开资料”列。
- 已公开、未公开、资料待审核状态与统计。
- 成员详情中的公开状态字段和开关。
- 核心人员的公开展示状态。

## 6. 添加成员

“添加成员”只直接创建新账号，不提供“选择已有账号”。通过招新录取转正的预备成员继续走招新结果流程，不经过本入口。

### 6.1 表单字段

- 姓名：必填。
- 学号：必填，作为初始登录账号，全平台唯一。
- 年级：必填。
- 班级：必填。
- 所属中心：必填。
- 成员职责：必填，下拉选项为“普通成员”“核心人员”。
- 白泽实践方向：所属中心为白泽时显示并必填。
- 个人简介：选填。
- 头像：选填。

创建后的成员身份固定为“正式成员”。

### 6.2 账号与首次改密

- 初始密码固定为 `hsd1314`。
- 首次登录后进入受限会话并强制跳转修改密码页。
- 新密码不得继续使用 `hsd1314`，确认密码必须一致。
- 完成修改前不能进入成员空间或其他受保护页面。
- 刷新后仍需保持强制改密状态。
- 从已有流程产生的账号不得因成员职责变化被重置密码。

当前前端只模拟流程。真实后端必须负责密码哈希、登录限流、会话吊销和强制改密状态，不能把明文密码写入浏览器持久化或数据库日志。

### 6.3 创建联动

创建成功后，同步产生：

- 可登录的平台账号。
- 正式成员档案。
- 管理端成员名单记录。
- 公开成员投影。
- 选择“核心人员”时的核心人员关系。

前端 Mock 中需要将这组变更作为一个动作处理；任何校验或持久化失败时不得出现只创建账号、未创建档案的半完成状态。后端接入后必须使用数据库事务。

## 7. 成员职责、核心人员与中心负责人

### 7.1 数据关系

- `memberDuty`：普通成员、核心人员。
- `centerLeadership`：独立的中心负责人关系。
- `adminQualification`：对应中心的管理员资格。

联盟规范规定中心负责人必然是核心人员，因此：

`isCore = memberDuty === 核心人员 || 存在中心负责人关系 || 关联的静态公开人员记录为核心人员`

授予中心负责人资格时自动进入核心人员名单。撤销负责人资格时，如果成员仍有手动核心人员关系或关联的静态公开核心关系，则继续保留核心人员；否则恢复为普通成员。

管理员资格不作为成员职责写入。公开页面可以组合展示“核心人员 · 中心负责人”。

### 7.2 核心人员页面

保留：

- 核心人员名单。
- 姓名、所属中心。
- 核心人员标识。
- “添加核心人员”。

删除：

- 任期。
- 公开状态。
- 编辑和移除功能。
- 公开预览卡片。
- 手动展示顺序和原型拖动手柄。

默认排序：四个中心负责人优先，其他核心人员随后；同组内按建立关系时间排序。

“添加核心人员”只从尚未成为核心人员的正式成员中选择。候选项显示姓名、所属中心和当前职责。中心负责人已经自动属于核心人员，不出现在候选列表。确认后只新增核心人员关系，不创建账号、不修改管理员资格。

## 8. 白泽实践方向统一

全平台只能存在一份白泽方向枚举：

- 鸿蒙开发
- 后端架构
- 大模型 AIGC
- UI/UX 设计
- 嵌入式开发

完整五项下拉框只用于白泽报名意向和白泽正式成员方向，不得复制第二份枚举。

规则：

- 报名第一志愿为白泽时显示并必选。
- 正式成员所属中心为白泽时显示并必选。
- 非白泽成员不得保存或显示实践方向。
- 切换到非白泽中心时清空已有方向。
- 管理端表格需要保留方向列时，非白泽显示 `—`。
- 公开名录、详情、中心成员列表和搜索仅对白泽成员使用方向。

当前通用自由文本 `direction` 会在报名资料、成员资料、管理成员记录和公开人员投影中造成冲突，需要迁移为可选的 `baizeDirection`。中心介绍、活动说明或素材分类中出现“鸿蒙开发”等普通内容文本不属于成员方向字段，无需删除。

个人简介在报名、添加成员和成员资料编辑中统一改为选填。空简介不产生空白公开段落。

## 9. 中心组织页面

- 删除四张中心卡片上的“配置中心资料”。
- 页面改为只读概览。
- 保留中心名称、简介、成员数、核心人员数、负责人和运行状态。
- 用户端中心介绍页面继续正常访问。
- 本次不创建中心资料编辑路由、弹窗或占位按钮。

## 10. 状态与错误处理

- 学号重复：阻止创建并将错误定位到学号字段。
- 白泽成员未选择方向：阻止提交。
- 非白泽成员携带方向：清空并拒绝非法持久化数据。
- 本地存储不可用：提示当前无法保存，不得显示成功。
- 成员详情身份变更：仅允许预备成员转正式成员；必须复用已有帐号并同步所有前端投影，正式成员不可降级。
- 报名记录不存在：返回 404。
- 导出结果为空：禁用导出。
- CSV 生成失败：保留当前筛选状态并允许重试。
- 停用模块旧地址：跳转到指定页面并显示一次提示。
- 首次改密失败：保留受限会话，不得绕过进入成员空间。

## 11. 数据与组件边界

- 上线功能开关：单一配置模块。
- 报名筛选、排序、详情解析和 CSV 序列化：独立纯函数，不直接耦合页面 DOM。
- 平台账号、成员档案、核心人员关系和管理员资格：分别建模，通过明确动作联动。
- `sessionStore.currentMemberId` 继续作为当前人员唯一权威。
- 公开页面继续通过成员仓储投影，不新增重复的“当前公开成员”状态。
- 浏览器持久化必须带 schema 版本并校验数据形状；损坏数据回退到安全的 Mock 初始值。

## 12. 验收与测试

至少覆盖：

1. 功能开关同时影响侧边栏、关联按钮和旧路由。
2. 招新批次保持现状。
3. 报名搜索、第一志愿筛选、最新/最早排序。
4. 每条“查看报名”进入正确详情，未知 ID 返回 404。
5. CSV 中文编码、列顺序、筛选范围、特殊字符和公式注入防护。
6. 新建成员、重复学号、浏览器持久化和跨页面投影。
7. 默认密码、首次强制改密和刷新后限制。
8. 正式成员默认公开，不存在公开状态开关。
9. 白泽五项方向枚举；非白泽隐藏、清空且不公开方向。
10. 个人简介选填及空内容渲染。
11. 预备成员转正式成员复用已有帐号、正式成员不可降级、持久化失败回滚，且管理端/公开投影刷新后身份一致。
12. 中心负责人自动成为核心人员。
13. 手动添加核心人员不修改管理员资格。
14. 核心人员页不存在任期、编辑、公开状态和拖动排序。
15. 中心组织页不存在“配置中心资料”。
16. 1440px、390px、键盘焦点、弹窗关闭和页面无横向溢出。
17. Typecheck、单元测试、生产构建和 Playwright E2E。

## 13. 本轮不实现

- 真实后端 API 和数据库。
- 生产级密码验证、找回密码、短信或邮件激活。
- 真实 XLSX 文件生成；本轮只固定后端契约。
- 核心人员任期、编辑、移除和手动排序。
- 中心资料编辑。
- 操作日志、回收站和独立上传任务页。
- 新建、删除或调整招新批次。
